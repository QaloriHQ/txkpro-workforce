TXKPRO™ WORKFORCE
CROSS-APP EVENT & SYNCHRONIZATION MAP
Version 1.0 — September 2026

PURPOSE
Define how one canonical backend event should surface across Institution, Employer, Student, and Admin experiences. Apps must not maintain competing copies of the same workflow state.

CORE RULE
WRITE ONCE → SHARED DOMAIN STATE → ROLE-SPECIFIC READ MODELS / NOTIFICATIONS

EVENT: ACCOUNT_CREATED
Source: Auth
Student: account pending verification/onboarding
Institution: no roster effect unless account is linked
Employer: employer user pending onboarding if applicable
Admin: identity visible in operational account view
Audit: AUTH_ACCOUNT_CREATED

EVENT: STUDENT_LINKED_TO_COHORT
Source: Institution roster/import/link
Student: institution/program/cohort displayed
Institution: roster count and student directory update
Employer: no visibility unless student later becomes discoverable
Admin: institution membership visible
Audit: STUDENT_LINKED_TO_COHORT

EVENT: READINESS_UPDATED
Source: Student or authorized Institution user
Student: readiness profile updates
Institution: readiness indicators/filter results update
Employer: permitted discoverable readiness fields update with provenance
Admin: audit/state available where authorized
Audit: READINESS_UPDATED

EVENT: SKILL_SELF_ATTESTED

Employer: may see self-attested status only if product policy permits, clearly labeled

Audit: SKILL_SELF_ATTESTED

EVENT: SKILL_VERIFIED

Admin: verification visible in audit/operations

Audit: SKILL_VERIFICATION_REVOKED

EVENT: REFERRAL_CREATED

Audit: REFERRAL_CREATED

EVENT: REFERRAL_VIEWED

Admin: telemetry

EVENT: INTERVIEW_REQUESTED

Audit: INTERVIEW_REQUESTED

EVENT: INTERVIEW_RESPONDED

EVENT: PLACEMENT_CREATED / HIRED

SYNCHRONIZATION REQUIREMENTS
1. Stable domain IDs are used across all apps.
2. No app copies canonical state into an app-specific database table simply for synchronization.
3. Role views may denormalize/cache for performance, but canonical write ownership stays singular.
4. Notifications are consequences of domain events, not the domain state itself.
5. Every consumer must tolerate delayed notification delivery without corrupting state.
6. Replayed jobs/webhooks must be idempotent.
7. Prototype localStorage simulation should mimic these event effects without claiming backend synchronization.

D-10 APPROVED CLARIFICATION — 2026-10-03
Official placement requires an authorized Employer or permitted workforce operator confirming the Student started employment. Scheduled starts remain pending_start; retention milestones remain separate. Recording a hire alone does not establish started employment. Historical and scoped official counts require explicit confirmation evidence. Existing active/ended status values and PLACEMENT_CREATED / PLACEMENT_STATUS_CHANGED audit vocabulary remain; no retention status is a placement status. Role, evidence, reporting, legacy-history and verification details: docs/D10_OFFICIAL_PLACEMENT.md (#202).

W12-16A OWNER-APPROVED EXPANSION — 2026-10-04 (#223)
STUDENT_PORTFOLIO_CHANGED is a publication/portfolio audit action, not a competency or hiring event. Source: active Student self membership; target student_portfolio. Payload: operation and record UUID only. Public profile reads curate opt-in canonical evidence and public projects/files; Employer file access reuses existing consent/talent scope. No skill, credential, placement, discoverability or reward state is implied. Contract: docs/W12_16A_STUDENT_PORTFOLIO.md.

APPENDIX C — OWNER APPROVED 2026-10-07
EMPLOYER_SCREENING_POLICY_ACCEPTED / EMPLOYER_SCREENING_POLICY_REVOKED: server-only Employer-scoped policy audit; acceptance payload includes actor_user_id, employer_id, policy_id, policy_version, accepted_at, scope, result and correlation_id. Separate from Candidate authorization.

APPENDIX D — COMM-02 OWNER APPROVED 2026-10-12 (#266)
COMMUNITY_POST_PUBLISHED: Source is an active authenticated Workforce member. Target is the canonical community_post/profile_post ID. Audit payload contains visibility and topic only; it never contains title, body or media. Consumers may refresh the signed-in feed. Search rendering/indexing is owned by COMM-03.
COMMUNITY_POST_REPORTED: Source is an active authenticated Workforce member. Target is the canonical community_post/profile_post ID. Metadata contains report ID and bounded reason. Consumers may enqueue moderation review; no automatic removal, reward, notification or hiring-state consequence is implied.

APPENDIX E — W12-20 OWNER APPROVED 2026-10-12 (#59)
COMMUNITY_COMMENT_PUBLISHED: Source is an active authenticated Workforce member. Target is the canonical comment ID; metadata contains the post ID and optional parent comment ID, never comment text. Consumers may refresh comment and profile-activity projections.
COMMUNITY_REACTION_SET / COMMUNITY_REACTION_WITHDRAWN: Source is an active authenticated Workforce member. Target is the canonical post ID; metadata contains reaction type only.
COMMUNITY_SHARE_CONFIRMED / COMMUNITY_SHARE_WITHDRAWN: Source is an active authenticated Workforce member. Target is the canonical post ID; metadata contains share or repost type only. W12-20 records internal confirmed activity; copying or opening an external target alone is not a confirmed external publication.
These events update community/profile read models only. They do not change private Workforce state, send notifications, or award PRO Points in W12-20. Delayed/replayed consumers must derive current state from the unique canonical interaction records.

APPENDIX F — W12-18 / W12-19 / W12-21 OWNER APPROVED 2026-10-13 (#57, #58, #60)
ORGANIZATION_PUBLIC_PROFILE_CHANGED: Source is an authorized Employer Owner/Admin or Institution Super Admin/Admin. Target is the canonical Employer or Institution ID. Audit payload contains visibility, canonical path and robots-index state only. It never contains private contact, Student, hiring, referral, placement, retention or screening data.
PROFESSIONAL_REVIEW_SUBMITTED: Source is an eligibility-checked Student, Educator or same-Institution leadership reviewer. Target is the canonical profile review ID. Audit payload contains status, numeric rating and verified-relationship boolean, never review text.
PROFESSIONAL_REVIEW_REPORTED: Source is an active authenticated Workforce member other than the review author. Target is the canonical profile review ID. Audit payload contains bounded reason and report ID; reporter identity stays in the private canonical report record.
PROFESSIONAL_REVIEW_MODERATED: Source is an authorized TXKPRO platform administrator. Target is the canonical profile review ID. Audit payload contains before/after moderation status only. Moderation never rewrites reviewer identity or review history.
SEO and sitemap rendering are projections of canonical publication state and do not create a domain event.

APPENDIX G — W12-16B OWNER APPROVED 2026-10-13 (#224)
PRO_SEASON_FINALIZED: Source is the TXKPRO season finalizer, triggered lazily by an authenticated points read or explicitly by a platform administrator. Target is the calendar-quarter start. Metadata contains Student count, level version, and scoring-snapshot presence. Consumers read immutable canonical standings; replay is idempotent and never recalculates an existing finalization.
PRO_SEASON_CORRECTION_RECORDED: Source is a new ledger award or reversal whose scoring season is already finalized. Target is the ledger entry ID. Metadata contains season, points delta, and entry type, never private source evidence. Consumers may show correction history but never mutate the finalized standing.
PRO_LEVEL_VERSION_CREATED: Source is a platform administrator. Target is the immutable level-version number. Metadata contains the future effective quarter and threshold count. It changes only future/effective level calculation and never rewrites a finalized season.

APPENDIX H — COMM-04 OWNER APPROVED 2026-10-13 (#268)
COMMUNITY_REPORT_SUBMITTED: Source is an active registered Workforce member. Target is the canonical moderation case. Metadata contains bounded target type/ID, reason and report ID; it never contains report narrative or content evidence. Submission alone has no hiring, credential, reward or account consequence.
COMMUNITY_USER_BLOCK_CHANGED: Source is the blocking member. Target is the other canonical user ID. Metadata contains mute, block or none only. Consumers suppress signed-in projections and interactions without deleting canonical content.
COMMUNITY_MODERATION_ACTIONED: Source is the versioned system policy or authorized platform/group moderator. Target is the moderation case. Metadata contains action, policy version, optional expiry and confidence, never raw evidence. Content removal may cause a separate COMMUNITY_POST_REMOVED event and any #274 award reversal through its own idempotent source contract; suspicion alone never proves fraud.
COMMUNITY_MODERATION_APPEALED: Source is the affected member, including a suspended member through the appeal-only surface. Target is the moderation case. Appeal text remains in the restricted canonical record and never enters the audit payload or analytics.
COMMUNITY_MODERATION_APPEAL_RESOLVED: Source is an authorized platform administrator. Target is the moderation case. Metadata contains upheld or reversed only. Reversal restores permitted state through an attributable action; it never rewrites prior audit history.

APPENDIX I — COMM-05 OWNER APPROVED 2026-10-14 (#269)
MESSAGE_REQUEST_CREATED: Source is an active registered Workforce member. Target is the request ID. Metadata contains recipient user ID and attachment count only; it never contains message text, filenames, storage paths or private profile data.
MESSAGE_REQUEST_RESOLVED: Source is the recipient. Target is the request ID. Metadata contains accept, decline, block or report and the resulting conversation ID when accepted. Acceptance converts the initial request into exactly one canonical message.
MESSAGE_SENT: Source is an active conversation participant. Target is the message ID. Metadata contains conversation ID and attachment count only. Consumers may update unread/notification state but must fetch participant-authorized content separately.
MESSAGE_REDACTED: Source is the message sender. Target is the message ID. The participant projection becomes a tombstone; the audit payload contains no message content.
Private message content and attachment metadata are excluded from analytics, advertising, search and notification payloads. A report captures only the specifically reported item in restricted moderation evidence; it never grants unrestricted inbox access.
COMM-09 domain events
- EVENT_RSVP_CHANGED — one member's canonical RSVP state changed; consumers must be replay-safe and must not infer attendee identity from aggregate projections.
- EVENT_CANCELLED — an event was cancelled; downstream engagement awards use an audited reversal rather than destructive deletion.

APPENDIX J — COMM-10 IMPLEMENTATION 2026-10-15 (#274)
PRO_ENGAGEMENT_AWARDED: Source is the active member performing the qualifying action. Target is the stable engagement-award ID. Metadata contains recipient user ID, canonical post/content IDs, action type and points delta; it never contains post, comment, poll, event or message content. Replay for the same recipient, actor, canonical content and action type does not create a second award.
PRO_ENGAGEMENT_REVERSED: Source is the member whose withdrawal changed the source or the canonical moderation/event transition that made the source ineligible. Target remains the same engagement-award ID. Metadata contains the negative points delta and canonical identifiers only. Restoration reactivates that award ID and emits a new PRO_ENGAGEMENT_AWARDED event.
Engagement awards are uncapped and separate from security.pro_award. Private messages, private/unlisted standalone content, private groups, sponsored content and organization-branded content never qualify.

APPENDIX K — ADS-01 OWNER APPROVED 2026-10-16 (#265, #275)
AD_DELIVERY_RECORDED: Source is the server-only native-delivery selector or measurement endpoint. Target is the immutable delivery-group UUID. Metadata contains campaign ID, creative ID, placement and event type only; it never contains creative copy, private member data or inferred traits. Served, viewable and clicked are distinct idempotent events. Consumers may aggregate delivery telemetry but may not create PRO Points or change hiring, credential, placement or retention state.
AD_DELIVERY_INVALIDATED and AD_PROVIDER_RECONCILED are reserved append-only correction events for the ADS-03 billing/reconciliation tranche. They never mutate the original evidence.
Advertiser, campaign and creative lifecycle events defined in #265 are emitted by the ADS-02 management workflow, not by ADS-01 delivery.

APPENDIX L — ADS-02 OWNER APPROVED 2026-10-16 (#264, #276)
ADVERTISER_STATUS_CHANGED: Source is open registration or an authorized TXKPRO administrator. Target is the canonical advertiser ID. Payload contains before/after status and bounded review context, never credentials or private Workforce data.
AD_CAMPAIGN_STATUS_CHANGED: Source is an authorized advertiser Owner/Admin or TXKPRO administrator. Target is the canonical campaign ID. Payload contains lifecycle state and bounded review decision. Draft saves and creative draft saves are separately auditable; creative copy remains in the restricted canonical creative record.
AD_CREATIVE_STATUS_CHANGED: Source is an authorized advertiser Owner/Admin/Creative or TXKPRO review. Target is the canonical creative ID. Approval follows its campaign review and never activates delivery without manual funding authorization.
Advertiser team invitations and acceptance are audited membership events. No ADS-02 event grants Workforce tenant access, publishes community content, creates PRO Points, or initiates live payment.

APPENDIX M — ADS-03 OWNER APPROVED 2026-10-16 (#265, #277)
AD_DELIVERY_INVALIDATED: Source is an authorized TXKPRO platform administrator. Target is the immutable delivery-group UUID. Metadata contains campaign/creative/placement identifiers and a bounded correction reason; original delivery evidence remains unchanged. Replays do not append a second invalidation.
AD_PROVIDER_RECONCILED: Source is an authorized TXKPRO platform administrator or separately approved server provider adapter. Target is the immutable delivery-group UUID. Metadata contains campaign ID, provider/reference and actual minor-unit amount. A provider/reference pair is idempotent and a conflicting replay fails closed. This event does not activate live charging or an external provider.
REPORT_EXPORTED: ADS-03 advertiser analytics export uses the existing canonical export event with advertiser scope, optional campaign ID, bounded UTC range and format only. Aggregate rows contain no viewer identity.
